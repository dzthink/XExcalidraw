# macOS / iOS 性能优化实施与验证

日期：2026-10-02。基于 [实施前审计](2026-10-02-audit.md)，保留原有侧栏宽度及 CSS 修改。Mind Elixir、Excalidraw 的库源码、版本、锁文件和依赖补丁均未修改；改动位于应用集成层、共享原生逻辑和测试设施。

## 已测结果

同一台 arm64 Mac、同一独立 WKWebView、1280×900、合成中文文档。最终两轮各预热 5 次、测量 30 次。rAF 间隔表示浏览器调度与渲染压力，**不是实际屏幕 FPS，也不是 iPhone 真机输入延迟**。挂载时间每轮只有一个样本，包含等待两个 rAF，不能当作冷启动 P95。

| 指标 | 实施前 | 最终两轮 |
| --- | ---: | ---: |
| 1000 节点导图，事务及 React 提交 P95 | 21ms | 3ms |
| 1000 节点导图，输入后 rAF 间隔 P95 | 103–104ms | 19–20ms |
| 1000 节点导图，挂载至两个 rAF | 636–644ms | 129ms / 129ms |
| 1000 节点大纲，已挂载富文本编辑器 | 1000 | 1 |
| 1000 节点大纲，事务及 React 提交 P95 | 7ms | 4–5ms |
| 1000 节点大纲，输入后 rAF 间隔 P95 | 约 17–18ms | 17–18ms |
| 5000 节点长正文，单节点输入数据层 P95 | 全文 change：17.23ms | 节点 changeContent：0.003ms |

Node 与 WebKit 的正文长度不同，不能将两张基准的耗时相加。最终数据层仍提供旧全文 change 的诊断结果；生产富文本输入已经改走节点路径。结构操作仍保留全文历史。历史预算根据序列化字符数估算，**不是实测堆内存上限**。

原始数据：[WebKit 最终](2026-10-02-webkit-optimized.json)、[WebKit 复测](2026-10-02-webkit-optimized-repeat.json)、[数据层最终](2026-10-02-document-optimized.json)、[导图/大纲交互](2026-10-02-editor-regression.json)、[Excalidraw 交互](2026-10-02-drawing-regression.json)。

## Web 编辑器

- 缓存节点数据及主题 DOM 索引；内容编辑只同步变化节点、前后选中节点和编辑节点。结构、根节点、布局或主题改变才刷新拓扑；不会每次插字都遍历节点、查询全图和比较整份 HTML。
- 内容撤销保存单节点快照，保留输入分组、跨视图历史、光标与结构撤销。每个历史栈最多 200 项，并使用约 16MiB 的序列化 UTF-16 大小预算；允许保留一项超过预算的最新操作。结构变更继续采用完整快照。
- 大纲非活跃行使用缓存的静态富文本，仅当前编辑行挂载 ProseMirror；只读大纲不挂载编辑器。点击在原位置恢复光标，键盘、撤销和富文本格式保持可用。
- ResizeObserver 观察实际尺寸；光标移动不主动重建连线。应用层的 SVG 适配器使用库公开的曲线生成器，先批量读取几何、再批量写入连线；结构刷新仍通过库正常流程。含箭头或概要时回退库的完整连线流程以保持其行为。
- 大图输入在上述优化后仍有约 85ms 的 rAF 间隔。对独立合成测试 WebContent 进程做 10 秒 Time Profiler 采样，常见栈为 `Document::updateEventRegions → RenderLayerBacking::updateEventRegion → Region::unite`；9907 个已解析样本中 4416 个自采样位于 `Region::unite`。应用新增覆盖画布的透明背景点击层，减少 WebKit 合并大量分散点击区域的开销；保留节点的命中优先级及库识别空白处的事件目标。最终复测降至 19–20ms。
- 桥接初始化采用引用计数，避免重复监听和重复分发。移除每 50ms 的鼠标样式轮询；桌面端由指针、按键及相关元素样式变化合并到单个 rAF 更新；iOS 不运行此桌面逻辑。
- Mind Map 和 Excalidraw 保存按 requestId 等待原生确认，确认对应 revision；保存中继续编辑会再保存最新 revision。重命名更新文档 ID，保留 Excalidraw 活跃实例和未确认编辑。原生不再在旧保存完成时盲目清除 dirty 状态。

四种布局中，根节点与下级节点变高后的应用连线路径均与库的完整重建一致。库自身的全图 linkDiv 诊断仍约 156–160ms，源码未改变；该诊断成本不能当作已优化的应用输入耗时。

## 原生主线程与生命周期

- 两端桥接 envelope 解析和出站编码/转义放到串行后台队列；WKWebView 调用与 UI 状态发布留在主线程。保存内层 JSON 解析、校验、草稿清理、文件元数据读取和写入放到保存队列。
- 保存提交时捕获当前目标与默认目录，后台不读取这些易变 UI 状态。晚到的保存可以更新索引，但不会重新激活已切走的文档；重命名映射仍确保迟到保存落到最新文件名。
- 索引持久化使用独立串行队列，合并未开始写入的快照；保留最新索引。扫描合并当前内存元数据，并在修订冲突时重新扫描，避免旧扫描覆盖保存或重命名结果。
- 两端目录树只在文件 URL 集合变化时响应索引更新，普通内容保存和最近打开时间更新不再直接引发树重建。真实目录结构变化、源变更和 watcher 请求仍保留现有处理。
- iOS 文件打开统一异步读取，并使用 generation 丢弃过期结果；先等待当前编辑保存确认，再激活目标文档。返回与页面退出会取消待打开结果并触发保存；加载与错误有对应反馈。
- 两端 UI 重命名改用异步保存队列。创建空白文件时先在后台写入和读取元数据，再在主线程更新索引。
- 共用异步 URL scheme 资源处理器，后台读取 bundle 与图片附件；取消任务后丢弃迟到回调。图片桥接的 base64 解码/编码移出 UI 路径。WKScriptMessageHandler 使用弱代理，消除 WebView 与 ViewModel 的强引用循环。

这些改动改变执行线程与调度方式，不代表 JSON 解析或文件系统自身变快；不能用原生纯 CPU 基线宣称未测量的主线程时长或 iCloud 延迟改善比例。

## 验证边界与后续候选

本轮已处理高频输入、保存、打开与资源读取路径。以下事项没有作为本轮已验证结果：

- iPhone 真机 Release 下的中文 IME composing、低端设备、多张大图片、长时间编辑与内存峰值；模拟器 UI 正确不等于真机流畅度已验收。
- iCloud 下载、协调与外部写入压力下的点击反馈和可编辑时间；异步读取不提供下载进度或完全取消底层文件读取。
- 大纲仍渲染所有展开行，只把完整富文本编辑器数量限制为一个；5000+ 行滚动的窗口化留待实测。
- 结构重排/折叠/布局切换仍可能触发库完整刷新；大目录的真实结构变化仍会构建树和扫描目录，尚未改为完整增量目录模型。
- 大图片仍有 Web/native base64 往返；尚未增加缩略图缓存、原生图片直写协议或 Web Worker 保存序列化。
- 主入口仍静态引入两类编辑器；尚未以拆包结果宣称冷启动改善。

上述项目继续遵守不修改 Mind Elixir 与 Excalidraw 库的约束。后续应优先用真机数据选择下一轮工作，而不是把合成 rAF 指标解释成所有交互已恒定达到 60fps。
